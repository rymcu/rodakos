RodakOS 划分为三个职责清晰、单向依赖的工程层次：

1. **Board / HAL 层**：由 RodakOS 自维护的 `components/rodakos_hal_boards/` 与 Espressif Board Manager 组成，原始设备句柄在 `main/rodakos_adapters/` 中完成适配，不再维护手写 `main/board/`。
2. **Phone OS 服务与内核层（`main/phone_os/`）**：统一承载应用注册表（`PhoneAppRegistry`）、单一生命周期宿主（`PhoneAppHost`）、导航与延迟队列（`PhoneNavigation`）、全局叠层（`PhoneShell`）以及经由 `PhoneServices` 注入的硬件与云端服务。
3. **Phone UI 与内置应用层（`main/phone_ui/`、`main/apps/`）**：围绕 320×240 屏幕封装 `PhoneUiLock`、4 套主题色板、布局工具、字库子集与 16 款静态注册的内置应用。

## 严格的 10 步启动顺序（`main.cc`）

改变以下顺序极易引发 LVGL 锁失败、白屏/黑屏或触控阻塞：

1. NVS 初始化
2. 早启动 USB MSC（U 盘模式）一次性闸门——在 `PhoneSystem` 启动前接管，避免与文件系统竞争
3. `esp_board_manager_init()`
4. 主题系统与 `PhoneUi`
5. LVGL Port 与 ST7789 显示驱动（双行缓冲 `320 × 24 × 2` = 30,720 B 内部 DMA 缓冲）
6. **GT911 缓存轮询桥**（低优先级后台任务读 I2C，LVGL 仅读缓存坐标）
7. 中文字库与 Ionicons 图标字体子集
8. LEDC 背光适配器
9. 系统服务实例化并注入 `PhoneServices`（编解码器、相机、语音、SD 均按需打开）
10. `PhoneSystem::Start()`（随后再异步启动 Wi-Fi 自动连接）

## 内部 SRAM 与 PSRAM 预算策略

在 ESP32-S3 上，真正的瓶颈往往不是总剩余内存，而是**最大连续内部 DMA SRAM 块**。RodakOS 采用以下硬约束：

- **PSRAM 优先**：LVGL 通过 `CONFIG_LV_USE_CUSTOM_MALLOC` 优先从 PSRAM 分配且绝不侵占内部 DMA 保留池；不触碰 NVS/Flash 的常驻任务栈（如 `touch_poll`、`qmi8658_motion`、`assistant_play`、`camera_capture`）使用 `xTaskCreate*WithCaps(..., MALLOC_CAP_SPIRAM)`。
- **固定 I2S 帧与外部任务回收**：ES8311 播放与 ES7210 采集统一采用四槽 16-bit I2S0 帧，防止反复重分配 TX DMA 环撕裂内部连续块；视频与语音任务通过统一的 `task-retirement` 外部回收机制释放栈与 TCB。
- **DVP DMA 缓冲控制**：保持 `CONFIG_CAM_CTRL_DVP_DMA_BUFFER_SIZE=8192`，本地/远程相机退出后最大连续内部 DMA 块回落恢复至 ≥ 8,192 B。

## 16 MB Flash 不可变 Recovery 分区布局

`partitions_16m.csv` 使用精确十六进制尺寸（避免简写 `1M` 引发容量计算错误）：

```csv
# Name,    Type, SubType, Offset,   Size,     Flags
nvs,       data, nvs,     0x9000,   0x6000,
otadata,   data, ota,     0xf000,   0x2000,
phy_init,  data, phy,     0x11000,  0x1000,
ota_state, data, nvs,     0x12000,  0x6000,
recovery,  app,  factory, 0x20000,  0x280000,
app,       app,  ota_0,   0x2a0000, 0xd50000,
coredump,  data, coredump,0xff0000, 0x10000,
```

- **为什么单大槽 + SD 暂存**：嵌入式语音唤醒模型与中文字库使主固件超过 6.5 MiB；通过 SD 卡暂存并验签 OTA 包，可保留高达 **13.3125 MiB** 的主应用槽，同时用 **2.5 MiB 不可变 Recovery** 保障刷写中断或新版本首启崩溃时自动回退救砖。
