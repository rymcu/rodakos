## Repository Facts

- ESP32-S3 target, 16MB flash, 8MB PSRAM, RYMCU BigSmart board.
- Toolchain: GCC on ESP-IDF 5.5.4 (Clang on Windows has response-file bugs; see `TROUBLESHOOTING.md`).
- `components/gen_bmgr_codes/` is generated by `idf.py bmgr` and is gitignored. Always run `.\fix_gen_paths.ps1` after `idf.py bmgr`.
- `build/` is gitignored.
- `partitions_16m.csv` lives at the repo root and uses hex sizes; shorthand like `1M` causes errors.
- Partition table: factory 8MB, storage ~8MB. Current `rodakos.bin` is about 3.7MB.
- `activate_idf.ps1` is the project-local ESP-IDF activator. It scans `C:\esp\<vX.Y.Z>\esp-idf\`, reads `C:\Espressif\tools\eim_idf.json`, and falls back to `$env:IDF_PATH`. Dot-source it once per shell: `. .\activate_idf.ps1`. The official Microsoft `*PowerShell_profile.ps1` is no longer required to run project scripts.

## Core Architectural Rules

- The board layer is esp-brookesia + Board Manager. Do not reintroduce a hand-written `main/board/`.
- RodakOS services open heavy hardware (codec, camera, voice) on demand, not at boot.
- WiFi credentials live in NVS via `WiFiConfig`; auto-connect starts after `PhoneSystem::Start()`.
- GT911 touch uses a cached polling bridge in `main.cc`. Do not call I2C inside the LVGL task.
- USB MSC mode is an early-boot, one-shot path in `main/usb_msc_mode.cc`. It must run before `PhoneSystem` starts.

## App Authoring

- Apps live in `main/apps/<app>/` and expose a `PhoneApp` subclass with `OnCreate / OnDestroy / OnResume / OnPause`.
- Register apps in `main/apps/built_in_apps.cc` through a `Register<App>App(registry)` helper.
- Add new app sources to `main/CMakeLists.txt`.
- Use the theme (`rodakos_theme.h`), layout helpers (`rodakos_layout.h`), and shared components (`phone_components.h`) instead of ad-hoc styling.
- Wrap LVGL calls in `PhoneUiLock lock(ui);`.

## Service Authoring

- New system services live in `main/phone_os/` and are exposed via `PhoneServices` (see `main/phone_os/phone_services.h`).
- Adapt raw esp-brookesia devices in `main/rodakos_adapters/` and inject them into services from `main.cc`.
- Document any esp-brookesia API references in adapter comments, not in service headers.

## Code Style

- Match surrounding code: comment density, naming, idioms.
- Use `ESP_LOGI / ESP_LOGW / ESP_LOGE` with component TAGs.
- Prefer `std::unique_ptr` for app and large object ownership.
- Use `static_cast` for type conversions; avoid C-style casts.
- Do not add comments that describe what the code does. Only document non-obvious WHY.

## Boot Order

`main.cc` must follow this sequence:

1. NVS
2. USB MSC boot gate
3. `esp_board_manager_init()`
4. Theme + `PhoneUi`
5. LVGL port + display
6. Cached touch polling bridge
7. Fonts
8. Backlight
9. Services (registered into `PhoneServices`)
10. `PhoneSystem::Start()`

If you change this order, expect LVGL lock failures, blank screen, or touch hangs. Verify against `TROUBLESHOOTING.md`.

## Validation

After non-trivial changes, expect to:

1. Activate the environment: `. .\activate_idf.ps1` (or pass `-Version` if multiple are installed).
2. Run `idf.py build`.
3. Check `build/rodakos.bin` size against the 8MB factory partition.
3. Flash with `.\flash_and_test.ps1 -Port COM<n>` and confirm a healthy boot log:
   - `RodakOS: Starting RodakOS with esp-brookesia HAL`
   - `Board manager initialized`
   - `Touch input registered with cached polling`
   - `LVGL port initialized`
   - `BacklightAdapter: Backlight adapter initialized`
   - `PhoneSystem: Starting Phone OS`
   - `HomeApp: Phone desktop ready with N apps`
   - `RodakOS: RodakOS started successfully`

If you cannot flash or observe the device, say so explicitly in the final report instead of claiming success.

## Git Workflow

- Branch: `main` is the default.
- Commit messages: short imperative summary, optional body. Match the existing style.
- Never commit `components/gen_bmgr_codes/`, `build/`, `sdkconfig.old`, screenshots, or `.vscode/settings.json`.
- Never run `git reset --hard`, `git push --force`, or skip hooks unless explicitly asked.
- Prefer a fresh commit over `--amend`.

## Non-Goals

- Runtime plug-in loading on ESP32-S3.
- OTA partitioning until the app/service set stabilizes.
